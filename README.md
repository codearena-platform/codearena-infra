# CodeArena Infrastructure

Infrastructure as code and Kubernetes manifests for the CodeArena platform.

## Directory Structure

- `terraform/`: creates the namespace, the datastore Helm releases and the application `Secret`.
- `k8s/`: Deployments and Services for the CodeArena services (`gateway`, `iam`, `competition`).

## Prerequisites

- [Terraform](https://developer.hashicorp.com/terraform/downloads) >= 1.5
- [kubectl](https://kubernetes.io/docs/tasks/tools/) configured for the target cluster
- A Kubernetes cluster with a LoadBalancer implementation (for the gateway Service)

No cloud provider CLI is required: Terraform only talks to the Kubernetes and Helm providers.

## Usage

The namespace must be the same for Terraform and `kubectl`. Pass it explicitly when it differs from the default (`codearena`):

```bash
export NAMESPACE=my-namespace
make tf-init   # initialize Terraform (configure a remote backend first for shared/prod use)
make tf-fmt-check
make tf-validate
make tf-plan   # review the infrastructure changes
make tf-apply  # create the namespace, datastores and the codearena-secrets Secret
make k8s-apply # deploy the applications
make k8s-delete
```

### Secrets

Passwords and keys are generated by Terraform (`random_password` / `random_id`) and written to the `codearena-secrets` Kubernetes Secret as:

| Key | Consumer |
| --- | --- |
| `POSTGRES_DSN` | competition |
| `MONGO_URI` | competition, iam |
| `JWT_SECRET` | iam |
| `ENCRYPTER_KEY` | iam |
| `REDIS_ADDR` | iam |

Terraform state therefore contains credentials. For anything beyond local development, configure an encrypted remote backend with restricted access before running `tf-apply`.

The workload images (`codearena-gateway`, `codearena-iam`, `codearena-competition`) are not published to a registry yet. Build and push them, then replace the `image:` values in `k8s/` with immutable tags or digests. `imagePullPolicy: Always` is used in the meantime so a stale cached `latest` image is not reused.

## Known gaps before production

- No ingress/TLS in front of the gateway `LoadBalancer`.
- No image build/push pipeline or immutable image references.
- No persistence sizing, backup/restore jobs or migration strategy for the datastores.
- No `simulation` / `realtime` services are deployed by this repository; the competition judge and gateway depend on them.
- Redis is deployed without authentication because `codearena-core`'s realtime service does not support a password yet.
- Helm chart versions are not pinned.
- No monitoring, alerting or log aggregation.
