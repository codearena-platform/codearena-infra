# CodeArena on-call runbook

This document covers alert routing and the first response to the four alert
classes shipped by `terraform/monitoring.tf`. It is intentionally kept in
`docs/` so the monitoring PR does not conflict with parallel README changes;
a maintainer will link it from the README once all parallel PRs have landed.

Set `NAMESPACE` for convenience:

```bash
export NAMESPACE="${NAMESPACE:-codearena}"
```

## What is deployed

| Component | Chart (pinned) | Purpose |
| --- | --- | --- |
| kube-prometheus-stack | `70.0.0` | Prometheus (15d retention), Alertmanager, Grafana, kube-state-metrics, node-exporter |
| Loki | `5.48.0` | Single-binary log store, filesystem chunks on a PVC, retention `168h` (7d) by default |
| Promtail | `6.17.1` | DaemonSet tailing `/var/log/pods`, labels `namespace`, `pod`, `container`, `node_name`, `app`, `environment` |
| prometheus-postgres-exporter | `8.3.0` | `pg_up` and Postgres metrics from `POSTGRES_DSN` |
| prometheus-mongodb-exporter | `3.23.2` | `mongodb_up` and MongoDB metrics from `MONGO_URI` |
| prometheus-redis-exporter | `6.38.0` | `redis_up` and Redis metrics from `REDIS_ADDR` |

Workload metrics come from kube-state-metrics (`kube_pod_*`, `kube_job_*`,
`kubelet_volume_stats_*`) and cAdvisor/container metrics. Datastores are
scraped via the three exporters, discovered through an annotation-based
`additionalScrapeConfigs` job (`prometheus.io/scrape=true` on their Services).
The dashboard **CodeArena Operational Overview** is provisioned into Grafana
from the `codearena-overview-dashboard` ConfigMap (label
`grafana_dashboard=1`, read by the Grafana sidecar).

### Useful entry points

```bash
# Grafana UI (admin password is generated by Terraform)
kubectl -n "$NAMESPACE" port-forward svc/kube-prometheus-stack-grafana 3000:80
kubectl -n "$NAMESPACE" get secret kube-prometheus-stack-grafana \
  -o jsonpath='{.data.admin-password}' | base64 -d; echo

# Alertmanager UI
kubectl -n "$NAMESPACE" port-forward svc/kube-prometheus-stack-alertmanager 9093:9093

# Prometheus UI (rules and graph)
kubectl -n "$NAMESPACE" port-forward svc/kube-prometheus-stack-prometheus 9090:9090
```

### Querying logs in Grafana (Loki)

Use Explore with the **Loki** data source (`http://loki:3100`):

```logql
{namespace="codearena"}
{namespace="codearena", pod=~"gateway-.*"}
{namespace="codearena", pod="simulation-abc123"} |= "error"
{namespace="codearena", container="postgres-backup"} |~ "error|fatal|panic"
{app="gateway", environment="prod"} |= "timeout"
```

Retention is set by `var.log_retention_period` (default `168h`) and enforced by
the Loki compactor, which needs a PVC that can hold at least the retention
window. Lower the period or raise `var.log_pvc_size` if the log volume grows.

## Alert routing

Alertmanager receives all rules from `additionalPrometheusRulesMap` and applies
this route tree:

- `severity=critical` → `codearena-pagerduty` (PagerDuty Events API v2).
- `severity=warning` → `codearena-slack` (Slack incoming webhook).
- everything else → `codearena-slack`.
- Alerts are grouped by `namespace` and `alertname`, with `group_wait=30s`,
  `group_interval=5m`, `repeat_interval=4h`.
- `CodeArenaPodCrashLoopBackOff` inhibits `CodeArenaPodRestarts` for the same
  pod to avoid duplicate pages.

The concrete destinations are supplied as sensitive Terraform variables, not
committed:

```bash
export TF_VAR_alert_slack_webhook_url='https://hooks.slack.com/services/...'
export TF_VAR_alert_pagerduty_routing_key='<Events API v2 integration key>'
export TF_VAR_alert_slack_channel='codearena-alerts'  # optional override
```

They overwrite the Helm values with `set_sensitive`, so neither secret appears
in a values file or in the dashboard ConfigMap. When a variable is empty the
receiver keeps a disabled placeholder (`http://127.0.0.1:1/slack-disabled` or
`disabled`); alerts are evaluated and visible in Alertmanager but **nothing is
delivered**. Treat an empty value as a monitoring outage. Rotate a leaked
webhook/key in the provider and then run `terraform apply`.

To verify routing without paging anyone, open Alertmanager → **Alerts**, select
a firing alert and use **Silence** first; a test notification can be sent from
the receiver configuration or with `amtool` from a pod that has network access.

## Assumptions

- ingress-nginx exports `nginx_ingress_controller_requests` (Helm value
  `controller.metrics.enabled=true`) in
  `var.ingress_controller_namespace`, and its metrics Service is annotated
  for Prometheus discovery. If your controller does not export metrics, the
  ingress alert stays pending — fix the controller rather than deleting the alert.
- The exporters read the existing `codearena-secrets` Secret. Using a
  different Secret name requires updating `terraform/monitoring.tf`.
- `k8s/monitoring-networkpolicy.yaml` must be applied with the rest of the
  manifests. It opens only scrape, datastore, log-push and notification paths
  on top of the deny-by-default policies.
- Loki is single-binary (no HA). For multi-node production, move chunks to
  object storage and run the distributed chart with the same retention values.

## Runbook

### Pod restarts / CrashLoopBackOff

Triggered by `CodeArenaPodRestarts` (>=3 restarts in 15m) or
`CodeArenaPodCrashLoopBackOff` (waiting 5m).

1. Identify the pod and check its last state:

   ```bash
   kubectl -n "$NAMESPACE" get pods -o wide
   kubectl -n "$NAMESPACE" describe pod <pod> | tail -40
   ```

2. Read the previous container's logs (do not just use `kubectl logs`):

   ```bash
   kubectl -n "$NAMESPACE" logs <pod> -c <container> --previous --tail=200
   ```

   In Grafana/Loki: `{namespace="codearena", pod="<pod>"} |= "error"`.

3. Common causes and actions:
   - Bad image digest: roll back `k8s/images.env` and re-apply (see README).
   - Missing/changed Secret or migration not applied: check
     `codearena-secrets`, then the migration Job alerts below.
   - Failed liveness probe on a slow start: confirm `/health` from inside the
     pod before changing probe settings.
   - OOMKilled: compare `container_memory_working_set_bytes` on the dashboard
     with the container limit and raise the limit or fix the leak.

4. Resolve the root cause, confirm the pod stays up for 15 minutes, then
   resolve the alert in Alertmanager. If a deployment is the cause, scaling it
   to zero is an immediate mitigation but removes service capacity — note it
   in the incident channel.

### PVC usage

Triggered by `CodeArenaPVCUsageHigh` (>85% for 15m) on any PVC in the
namespace, including `data-...postgresql/mongodb`, `redis-data-...`,
`datastore-backups` and `core-data`.

1. Confirm which volume and how fast it is growing:

   ```bash
   kubectl -n "$NAMESPACE" get pvc
   kubectl -n "$NAMESPACE" exec deploy/simulation -- df -h /data
   ```

   The dashboard panel **PVC usage by volume (%)** shows the trend.

2. For `datastore-backups`, check the retained dumps and remove stale files
   only after confirming the seven-day retention policy:

   ```bash
   kubectl -n "$NAMESPACE" exec <backup-pod> -c postgres-backup -- ls -lh /backups/postgresql
   ```

3. For a datastore PVC, check growth (`pg_total_relation_size`, MongoDB
   `db.stats()`), clean up application data only with product approval, and
   expand the PVC if the StorageClass allows it:

   ```bash
   kubectl -n "$NAMESPACE" patch pvc <pvc> \
     -p '{"spec":{"resources":{"requests":{"storage":"40Gi"}}}}'
   ```

   Also raise the matching `var.*_pvc_size` in Terraform so the next apply
   does not shrink it back. Expanding a PVC does not replace a backup: verify
   the latest dump before making changes.

### Failed migration or backup Jobs

Triggered by `CodeArenaSchemaMigrationJobFailed`
(`job_name=~"schema-migrations-.*"`) or `CodeArenaBackupJobFailed`
(`job_name=~"datastore-backup-.*"`).

1. Inspect the Job and its pod logs:

   ```bash
   kubectl -n "$NAMESPACE" get jobs | grep -E 'schema-migrations|datastore-backup'
   kubectl -n "$NAMESPACE" logs job/<job-name> --all-containers=true --tail=200
   kubectl -n "$NAMESPACE" describe job/<job-name> | tail -30
   ```

2. Migration Job:
   - A checksum guard failure means someone edited an applied version; fix it
     with a **new** migration version, never by editing the old file.
   - Connection/authentication errors: verify `POSTGRES_DSN`/`MONGO_URI` in the
     Secret and that the datastores are ready.
   - Re-run only after the cause is fixed: `make k8s-migrate`. The migration is
     idempotent. Do not promote new images until it succeeds.

3. Backup Job:
   - Verify the last successful dump and the backup PVC free space (previous
     section). A full PVC or an unreachable datastore are the usual causes.
   - Re-run with `kubectl -n "$NAMESPACE" create job --from=cronjob/datastore-backup <unique-name>`.
   - Treat a missed daily backup as an incident: other failures reduce
     recoverability. If dumps are more than 24h old, pause risky changes and
     take a manual dump.

4. Failed Jobs remain for three revisions (`failedJobsHistoryLimit`), so the
   alert clears when the failing object ages out. Resolve it explicitly only
   after the next scheduled/manual run succeeds.

### Ingress error rate

Triggered by `CodeArenaIngressHighErrorRate` (>5% 5xx for 5m) for
`var.ingress_host`.

1. Check the ingress controller and gateway health:

   ```bash
   kubectl -n ingress-nginx get pods
   kubectl -n "$NAMESPACE" get ingress gateway
   curl -fsS -k https://<ingress-host>/health
   kubectl -n "$NAMESPACE" get deploy gateway iam competition simulation
   ```

2. Correlate in Grafana: the **Ingress 5xx rate** panel plus Loki queries
   `{namespace="codearena", app="gateway"} |= "error"` and the same for
   `iam`, `competition` and `simulation`. The dashboard's
   **Datastore exporter availability** panel rules out an upstream datastore.

3. Common causes:
   - Upstream restart/CrashLoop: follow the pod-restart section.
   - 502/503 after a release: roll back image digests in `k8s/images.env` and
     re-apply.
   - TLS/certificate or DNS problem: verify the `codearena-tls` Secret and DNS.
   - Ingress controller overloaded: check controller CPU/memory and scale it.

4. Once 5xx is back below 5% for five minutes, resolve the alert and record
   the customer-visible duration in the incident notes.
